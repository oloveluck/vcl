9.3

vcl: the ValueSet Compose Language🔗

Health data is full of codes. A lab result says which test it was with a code; a diagnosis, a medication, a marital status are codes too. Rules about that data keep needing to say "one of these codes": the tests used to follow diabetes, the codes that mean a parent. Such a named set of codes is a value set. You name the set once, and a profile, a search or a piece of clinical logic can then refer to it instead of repeating the codes.

The codes themselves come from code systems: published catalogues of codes with their meanings, such as LOINC for laboratory tests or SNOMED CT for clinical terms. Each code system is named by a web address (http://loinc.org).

FHIR writes a value set as a ValueSet resource, which is a page of JSON. VCL, the ValueSet Compose Language, writes the same thing on one line:

(http://loinc.org)(4548-4;2345-7)

That reads "from LOINC, the codes 4548-4 and 2345-7": the HbA1c test and the glucose test. A value set can also describe its codes by a rule instead of listing them, "every code under parent", and VCL writes that as shortly.

This package turns a VCL expression into the ValueSet resource, turns a ValueSet back into VCL, and lets the rest of the family use an expression wherever a value set is expected. A mistake in an expression is reported where the expression stops.

Part of the fhir family of FHIR languages and tools.

1 What you can do with it🔗

  • Write a value set in one line and get the FHIR resource: A first example.

  • Describe codes by a rule instead of listing them, so the set stays right when the code system grows (Describing codes by a rule).

  • List the codes a value set holds, with their names: this is called expanding it (Listing the codes: expanding).

  • Read a ValueSet someone published as one line of VCL (Reading a ValueSet as VCL).

  • Keep a value set in a file that a program can use (As a module).

2 A first example🔗

1. Install the tools as the family’s front page describes. The command is then raco vcl (or vcl, if you built the standalone tools).

2. Write an expression. FHIR has a small code system for a person’s administrative gender, with four codes. This expression names two of them:

$ raco vcl '(http://hl7.org/fhir/administrative-gender)(male;female)'

{"compose":{"include":[{"concept":[{"code":"male"},{"code":"female"}],"system":"http://hl7.org/fhir/administrative-gender"}]},"name":"VCLExpression","resourceType":"ValueSet","status":"active","url":"http://fhir.org/VCL?v1=(http://hl7.org/fhir/administrative-gender)(male;female)"}

The first pair of round brackets holds the code system, the second the codes, separated by semicolons. Put the expression in single quotes so the shell leaves the brackets alone.

The answer is a ValueSet resource, one line of JSON. Reading it:

  • compose is the part of a ValueSet that says which codes are in it. It includes one group: from this system, these two concepts. FHIR calls a code together with its meaning a concept.

  • url is the address the value set goes by. A VCL value set needs no address of its own: its address is http://fhir.org/VCL?v1= followed by the expression. Anything that takes a value set’s address can be given this one.

  • name and status are filled in so the resource is complete.

3. List the codes it holds. The family’s terminology tool, fhir-tx, takes that address:

$ raco fhir-tx expand 'http://fhir.org/VCL?v1=(http://hl7.org/fhir/administrative-gender)(male;female)'

{"expansion":{"contains":[{"code":"male","display":"Male","system":"http://hl7.org/fhir/administrative-gender","version":"5.0.0"},{"code":"female","display":"Female","system":"http://hl7.org/fhir/administrative-gender","version":"5.0.0"}],"total":2},"resourceType":"ValueSet","url":"http://fhir.org/VCL?v1=(http://hl7.org/fhir/administrative-gender)(male;female)"}

This is the value set expanded: the list of the codes it holds, each with its name (display), looked up in the code system. Here that is no surprise, since you listed them.

4. Describe instead of listing. A star means "every code of the system":

(http://hl7.org/fhir/administrative-gender)*

Expanded the same way, this holds four codes: male, female, other and unknown. You did not have to know them. Put - (http://hl7.org/fhir/administrative-gender)unknown after it, "without unknown", and it holds three.

5. Make a mistake. Leave out the last bracket:

$ raco vcl '(http://hl7.org/fhir/administrative-gender)(male;female'

<expression>:1:50: vcl parse error: the expression ends after `female`

 1 | (http://hl7.org/fhir/administrative-gender)(male;female

   |                                                  ^^^^^^

The message gives the line and column, and the marker shows the last thing that was understood.

6. Go the other way. Given a ValueSet as a JSON file, here the value set of marital statuses that FHIR itself publishes, --decompile prints it as VCL:

$ raco vcl --decompile ValueSet-marital-status.json

(http://terminology.hl7.org/CodeSystem/v3-MaritalStatus)*;(http://terminology.hl7.org/CodeSystem/v3-NullFlavor)UNK

Which reads: every code of the marital-status code system, and the code UNK (unknown) from another one.

3 Writing an expression🔗

An expression is one line. The specification at build.fhir.org is the reference for the language; this section is what you need most of the time.

3.1 Listing codes🔗

  • (http://loinc.org)(4548-4;2345-7): a code system in round brackets, then its codes in round brackets, separated by ;. A space after the semicolon is allowed.

  • (http://loinc.org)4548-4: one code needs no second pair of brackets.

  • (http://loinc.org|2.74)(4548-4;2345-7): a bar and a version after the address pin the codes to one version of the code system.

  • (http://loinc.org)4548-4;(http://snomed.info/sct)73211009: codes from two code systems, joined by ;.

  • A code with characters a plain code cannot have (a space, a dot) goes in double quotes: "B.123".

Always give the code system. The same code can mean different things in different systems, and the round brackets around the address are how VCL knows where the address ends: without them http://loinc.org|4548-4 is read as one long address.

3.2 Describing codes by a rule🔗

Many code systems are trees: a general code with more specific ones under it. HL7’s code system of roles and personal relationships has PRN (parent), and under it father, mother, adoptive parent, step parent and more. To name "any kind of parent" you do not list them. You write a filter, a rule the codes must meet:

(http://terminology.hl7.org/CodeSystem/v3-RoleCode)concept<<PRN

concept<<PRN means "PRN and every code below it". Expanded (Listing the codes: expanding shows the command), this holds 18 codes, from PRN parent through FTH father and MTH mother to STPPRN step parent. If the code system later gains a new kind of parent, the value set holds it without being edited. That is the reason to describe rather than list.

Other rules are written the same way, a property of the code, an operator and a value:

  • concept<PRN: the codes below PRN, without PRN itself (17 of them).

  • concept<!PRN: its direct children only (6: adoptive parent, father, mother, natural parent, foster parent, step parent).

  • COMPONENT="Hemoglobin A1c": a property of the code has this value. Which properties exist depends on the code system; this one is LOINC’s.

Every form lists every operator.

3.3 Everything, another value set, leaving out🔗

  • (http://hl7.org/fhir/administrative-gender)*: every code of a code system.

  • ^http://hl7.org/fhir/ValueSet/administrative-gender: the codes of another value set, named by its address after a ^.

  • (http://loinc.org)(4548-4;17856-6) - (http://loinc.org)17856-6: what is on the left, without what is on the right. Leave spaces around the - or bracket both sides: a hyphen straight after a code is read as part of the code.

3.4 Or, and🔗

; means "or": the codes of either side. , means "and": the codes that meet both rules.

(http://terminology.hl7.org/CodeSystem/v3-RoleCode)(concept<<PRN,concept~<<FTH)

That is "a kind of parent, and not a kind of father" (13 codes). A code system in round brackets applies to everything in the brackets that follow it.

VCL gives ; and , no order of precedence, so an expression that mixes them must say which goes first with brackets. p=a;(q=b,r=c) is "p is a, or both q is b and r is c". Written without the inner brackets, p=a; q=b, r=c is refused with unexpected comma.

The words in brackets are the names FHIR gives these operators in a ValueSet’s filter. Spaces are allowed; a line break is not.

4 Listing the codes: expanding🔗

A value set says which codes are in it; it does not have to list them. Expanding a value set is working out the list. The terminology tool fhir-tx does it, and it takes a VCL value set by its address, http://fhir.org/VCL?v1= followed by the expression:

$ raco fhir-tx expand 'http://fhir.org/VCL?v1=(http://terminology.hl7.org/CodeSystem/v3-RoleCode)concept<!PRN' --package hl7.fhir.r4.core.tgz

{"expansion":{"contains":[{"code":"ADOPTP","display":"adoptive parent","system":"http://terminology.hl7.org/CodeSystem/v3-RoleCode","version":"2018-08-12"},{"code":"FTH","display":"father", … {"code":"STPPRN","display":"step parent","system":"http://terminology.hl7.org/CodeSystem/v3-RoleCode","version":"2018-08-12"}],"total":6},"resourceType":"ValueSet","url":"http://fhir.org/VCL?v1=(http://terminology.hl7.org/CodeSystem/v3-RoleCode)concept<!PRN"}

Quote the address: it holds brackets and semicolons the shell would otherwise act on.

What expanding needs is the content of the code system: its codes, their names, and which code is under which. A rule such as "everything below PRN" cannot be worked out from the expression alone. The tool reads code systems from FHIR packages. With no --package it reads the FHIR R5 core package; the relationship codes above are in the R4 core package, which is why the command names it. The same command without --package answers with no codes:

$ raco fhir-tx expand 'http://fhir.org/VCL?v1=(http://terminology.hl7.org/CodeSystem/v3-RoleCode)concept<!PRN'

{"expansion":{"contains":[],"total":0},"resourceType":"ValueSet","url":"http://fhir.org/VCL?v1=(http://terminology.hl7.org/CodeSystem/v3-RoleCode)concept<!PRN"}

So an empty expansion of a rule usually means the code system was not at hand, not that the rule matches nothing. The two largest code systems, LOINC and SNOMED CT, are not in the packages that come with the tools, so a rule over them does not expand here.

Codes you listed are treated differently. When the code system is at hand, each is looked up in it: it gets its name, and a code the system does not have drops out. When it is not, the codes are given back as you wrote them, without names:

$ raco fhir-tx expand 'http://fhir.org/VCL?v1=(http://loinc.org)(4548-4;2345-7)'

{"expansion":{"contains":[{"code":"4548-4","system":"http://loinc.org"},{"code":"2345-7","system":"http://loinc.org"}],"total":2},"resourceType":"ValueSet","url":"http://fhir.org/VCL?v1=(http://loinc.org)(4548-4;2345-7)"}

Is this code in the set? is the other question to ask of a value set:

$ raco fhir-tx validate-code 'http://fhir.org/VCL?v1=(http://hl7.org/fhir/administrative-gender)(male;female)' http://hl7.org/fhir/administrative-gender other

{"parameter":[{"name":"result","valueBoolean":false},{"name":"code","valueCode":"other"},{"name":"system","valueUri":"http://hl7.org/fhir/administrative-gender"},{"name":"message","valueString":"The code 'other' is not in the value set"}],"resourceType":"Parameters"}

The same address works wherever the family takes a value set’s address: a binding in a profile, the $expand and $validate-code operations, FHIRPath’s %terminologies.expand(). The fhir-tx page describes the terminology tool.

5 Reading a ValueSet as VCL🔗

A published ValueSet can be long, and most of it is not about which codes are in it. --decompile prints the part that is, the compose, as one line. This is the value set of vital signs from the FHIR R4 core package:

$ raco vcl --decompile ValueSet-observation-vitalsignresult.json

(http://loinc.org)(85353-1;9279-1;8867-4;2708-6;8310-5;8302-2;9843-4;29463-7;39156-5;85354-9;8480-6;8462-4;8478-0)

The file may be a whole ValueSet or just a compose. Compiling the printed line gives the same compose back. What VCL has no place for is left out: the names (displays) written beside the codes and a few rarely used settings (Limits).

6 Running it🔗

6.1 Command line🔗

The command turns an expression into a ValueSet, or a ValueSet into an expression.

raco vcl '<expression>'

  

the ValueSet as JSON, under the address made from the expression

raco vcl expression.vcl

  

the same, the expression read from a file

raco vcl --decompile valueset.json

  

the VCL of a ValueSet's compose

A file holds one expression on one line. It may begin with a #lang vcl line (As a module) and end with a line break. An error in a file is reported at the file’s own line:

$ raco vcl broken.vcl

broken.vcl:2:50: vcl parse error: the expression ends after `female`

 2 | (http://hl7.org/fhir/administrative-gender)(male;female

   |                                                  ^^^^^^

The argument is read as a file when a file of that name exists, and as an expression otherwise. So a mistyped file name is taken for an expression: check the spelling if the answer looks strange.

An error is reported as text by default. --format json writes it as JSON and --format outcome as a FHIR OperationOutcome, for a program to read. The command exits with 0 when all is well, 1 on a VCL error, and 2 when it was called wrongly or cannot read the file to decompile.

6.2 As a module🔗

A file whose first line is #lang vcl is a Racket module, so a program can require it. The expression is checked when the program is built: a mistake stops the build, at the line and column in the .vcl file where the expression stops.

#lang vcl

(http://hl7.org/fhir/administrative-gender)(male;female)

Saved as sexes.vcl, (require "sexes.vcl") gives source (the text), expression (the parsed expression), compose (the ValueSet.compose as JSON data) and valueset (the whole ValueSet, under the address made from the expression). Requiring the module also registers the value set, so a profile’s binding and $expand find it by that address. racket sexes.vcl prints the ValueSet, indented.

(require (only-in "sexes.vcl" [valueset sexes])
         (only-in fhir/terminology/operations $expand))          ; fhir-tx
(hash-ref ($expand #:valueSet sexes) 'expansion)                ; the codes: male, female

6.3 From Racket🔗

The steps the module form does for you are functions. Each answers a Result (fhir/result/result): (ok value), or (err e) for an expression that is refused.

(require vcl/compile vcl/decompile fhir/result/result)
(ok-value (vcl->valueset "(http://loinc.org)(85354-9;55284-4)"))   ; a ValueSet jsexpr
(ok-value (vcl->valueset "(http://loinc.org)4548-4"                ; under an address of your own
                         #:url "http://example.org/ValueSet/a1c" #:name "A1c"))
(define c (ok-value (vcl->compose "(http://loinc.org)(85354-9;55284-4)")))   ; just the compose
(compose->vcl c)                         ; back to text: "(http://loinc.org)(85354-9;55284-4)"
(validation-error-message (err-error (vcl->compose "*")))          ; why an expression was refused

7 In an editor, and for an AI agent🔗

  • In an editor. The family’s language server, fhir-lsp, underlines a mistake in a .vcl file as you type: it compiles the one expression. It loads vcl/support for this.

  • For an agent. In an fhir-mcp workspace a file diabetes-labs.vcl is a value set whose address is the workspace’s own address followed by /ValueSet/diabetes-labs, and the workspace’s CQL libraries, profiles and validation find it by that address. Running the file expands it, and explain with a system and a code says which part of the expression lets the code in or keeps it out. This is vcl/workspace. The repository’s guide.md is the language written for an agent to read (fhir-mcp serves it as learn://vcl), and .claude/skills/vcl is the same workflow for an agent using the command line.

8 Limits🔗

  • VCL can say more than a ValueSet can hold. These are valid VCL, but a ValueSet’s compose has no way to write them, so they are refused with a message that says so: taking codes out anywhere but at the top level of the expression; "and" between plain codes, a value set or *, or around an "or" in brackets (only rules can be combined with "and"); two different code systems inside one "and"; a * with no code system. For example (http://loinc.org)(4548-4; 17856-6), (http://loinc.org)17856-6 gives conjunction of non-filter terms is not compose-expressible.

  • Give the code system. A code written with no code system compiles to a group that names none, which is not a valid ValueSet.

  • Expanding needs the code system, and LOINC and SNOMED CT are not shipped. A rule over a code system that is not at hand expands to no codes, without a warning (Listing the codes: expanding).

  • Lists of rules. A list of filters inside ^{…} and the source of an of ({concept<B}.prop) are stored in the ValueSet as VCL text, in the filter’s value.

  • The of operator matches nothing when the terminology tool expands a VCL value set. Every other operator expands, >> and !!< included.

  • Decompiling loses what VCL cannot say: a group that has both listed codes and rules keeps the codes only; names (displays) and designations of codes, and the compose’s inactive and lockedDate, are dropped.

  • The address. In the address made from an expression only spaces are escaped (as %20); other characters are left as written.

  • One expression, one line. A file holds a single expression, and the specification does not allow a line break inside it.

  • One difference from the official grammar: a list with a single code, prop^{a}, is accepted here, so that a decompiled value set with a one-code list compiles again.

9 Words used here🔗

  • Code: a short identifier with an agreed meaning, such as 4548-4 for the HbA1c test. Concept: FHIR’s word for a code together with its meaning.

  • Code system: a published catalogue of codes (LOINC, SNOMED CT, FHIR’s own small ones), named by a web address. A CodeSystem resource carries its content.

  • Value set: a named set of codes, drawn from one or more code systems. In FHIR, a ValueSet resource.

  • Compose: the part of a ValueSet that says which codes are in it: groups to include and to exclude, each a code system with listed codes or filters. A VCL expression is a compose on one line.

  • Filter: a rule that picks codes by a property instead of listing them, such as "PRN and everything below it".

  • Expansion, expanding: the list of the codes a value set actually holds, and working it out. It needs the content of the code systems.

  • Display: the human-readable name of a code ("father" for FTH).

  • Implicit url: the address a VCL value set goes by without being given one, http://fhir.org/VCL?v1= followed by the expression.

  • Binding: the statement in a profile that an element’s code must come from a given value set.

  • Package: a .tgz file of FHIR resources, such as the FHIR core specification. It is where the tools find code systems.

  • Terminology service: the tool that answers questions about codes: expand a value set, check a code. Here, fhir-tx.

  • Decompile: to turn a ValueSet back into the VCL that states it.

10 How it is tested🔗

  • All 60 example expressions on the VCL specification’s page are read, written back as text and read again, giving the same expression each time.

  • A compose turned into VCL and compiled again is the same compose.

  • Every example in the repository’s guide.md is compiled, and its table of operators is compared with what the compiler does.

raco test . in the repository runs them all. The repository’s TESTING.md has the table.

vcl/parser/parse🔗

 (require vcl/parser/parse) package: vcl

procedure

(parse-vcl src) → result?

  src : string?
(ok ast) or (err invalid-encoding) with a fhir/diagnostic attached (attached-diagnostic), positioned in the expression. Memoized.

The AST is prefab (vcl/parser/ast): vcl-sub (a system applied to an expression), vcl-conj (,), vcl-disj (;), vcl-excl (-), vcl-code, vcl-star, vcl-include (^uri), vcl-filter (property, operator, value), vcl-of, vcl-code-list, vcl-filter-list.

vcl/compile🔗

 (require vcl/compile) package: vcl

procedure

(vcl->compose x) → result?

  x : (or/c string? any/c)
Text or an AST to (ok compose). A disjunction becomes include entries, a conjunction one include’s filters, a top-level - the exclude, a system distributes over its members, ^uri is a valueSet reference. What a compose cannot say is an err, never an exception: an exclusion below the top level, a conjunction of plain codes, a bare *.

procedure

(vcl->valueset src [#:url url #:name name]) → result?

  src : string?
  url : (or/c string? #f) = #f
  name : (or/c string? #f) = #f
An active ValueSet. url defaults to the implicit VCL url of src; name to "VCLExpression".

procedure

(vcl-print ast) → string?

  ast : any/c
Canonical text, compound members bracketed.

 (require vcl/decompile) package: vcl

procedure

(compose->vcl compose) → string?

  compose : jsexpr?
A ValueSet.compose as VCL. For compose-expressible expressions, compiling the result gives the compose back.
